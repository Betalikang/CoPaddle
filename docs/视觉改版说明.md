# 视觉改版说明

> 目标：让前端在评委面前「眼前一亮」。
> 前提：不动 git 历史、保留工作区原有未提交改动、不改业务语义。

上一版的问题不是「不好看」，而是**没有表达产品是什么**：白底 + 正中央大标题 + 三张同构圆角卡 + 一个橙色点缀，这套骨架可以原样贴给任何一个 SaaS 后台。CoPaddle 真正稀有的东西是**可以被摊开逐条核对的记录**——约束求解出来的分组、可以拖动的任务 DAG、带上下界的贡献区间账本——界面却完全没有体现这件事。

所以整轮改版只围绕一个方向：**一份可以被查看的调度记录**。

## 一、三个可执行的决策

### 1. 底色从「中性白」换成「纸」

`--background` 由纯白改为 `hsl(200 30% 97%)` 的冷纸，卡片仍是纯白。层级关系从「阴影浮起」变成「比纸更亮」——因为账本类界面的层级应该像纸叠纸，而不是像一堆浮在空中的卡片。圆角同步从 `0.6rem` 收到 `0.375rem`：上一版的软圆角让标题、卡片、按钮看起来是同一种东西，收掉之后表格与清单才显得利落。

### 2. 强调色压暗，并且刻意稀缺

这是本轮唯一一处**必须改**的硬问题。原色板 `--brand: hsl(25 95% 53%)` 当文字色铺在白底上只有 **2.78:1**（纸底 2.61:1），白字压在它上面也是 2.78:1 —— 也就是说全站每一处 `text-brand` 实际都过不了 WCAG AA，只是橙色看起来足够醒目，没人去算。

新值 `hsl(18 92% 40%)` = `#c44008`：纸底 **4.82:1**、白底 **5.13:1**、白字压其上 **5.13:1**。一个值同时满足「当文字」和「当填充」，不必再为两种用途维护两支色。

同时把 `--primary` 改成墨色，让按钮默认是墨底浅字（15.8:1）。**按钮不再是品牌橙**是有意的：一屏里橙色一多，「需要看的那一处」就不成立。落地页实测 `text-brand` 只有 3 处、`bg-brand` 1 处（`design-check` 断言 `<= 6`）。

> 中途试过 `hsl(22 93% 48%)` = `#ec5c09`，纸底只有 3.22:1、白字压其上 3.44:1，两边都不合格，否决。**改色前请先用脚本复算，别退回亮橙。**

### 3. 全站只留一处进场动效

`lane-draw`（航道线从左展开 900ms）+ `lane-dot`（节点延迟亮起），只用在落地页的五段航道上。每段都 fade-in-up、每张卡都 hover 抬起，是生成式页面的典型痕迹，刻意没做。另外加了 `prefers-reduced-motion: reduce` 兜底，让航道直接显示终态。

### 两个容易漏掉的残留

雷达图与 DAG 节点环原本都把颜色**写死在组件里**（`stroke="#f97316"`、`rgba(253,186,116,0.9)`）。这类写死的值换色板时不会跟着变，而且截图里看不出来——橙色还是橙色，只是不是同一支橙。现在都改成取 `var(--brand)`，并在 `design-check` 里加了断言：浅色下必须是 `rgb(196, 64, 8)`、深色下必须**不同于**浅色（实测深色是 `rgb(251, 140, 55)`）。两者不同，才说明它真的在跟随主题。

## 三、登录页左栏为什么用固定深色

左栏没有走 `bg-foreground text-background text-brand`，而是固定 `hsl(205 42% 9%)` + `hsl(26 96% 66%)` 的橙标题。原因：深色主题的 `--brand` 是提亮到 60% 的橙 `#fb8c37`，压在浅色背景上只有 **2.21:1**；如果左栏跟随主题翻转成浅色面板，那三行小标题会读不清。

墨底 `rgb(13,25,33)` 上的实测值：白字 96% 不透明度 16.46:1、70% 9.12、65% 8.04、50% 5.24、**45% 恰好 4.50（卡在 AA 线上）**、橙标题 8.57。因此底部小字从 `white/45` 提到 `white/55`。

## 四、验收

四条命令，全部需要生产构建 + `next start`：

```bash
node scripts/design-check.mjs    <cookie> <courseId>   # 19 项设计意图断言
node scripts/contrast-audit.mjs  <cookie> <courseId>   # 8 页 × 浅深两主题，WCAG AA
node scripts/a11y-check.mjs <courseId> <teacher> <captain>   # 17 项交互与无障碍
node scripts/screenshots.mjs     <cookie> <courseId>   # 14 张截图 + 横向溢出检查
```

实测结果：

| 检查 | 结果 |
|---|---|
| `pnpm verify`（tsc + vitest + build） | EXIT=0；增加两项分组加载回归用例后，9 files / 69 tests |
| `design-check.mjs` | **19 项全 PASS**（Hero 65.6px / 对比 15.54:1 / 橙色 3+1 处 / 航道动画 `lane-draw` / 雷达图跟随主题） |
| `contrast-audit.mjs` | **浅深两主题 0 处不合格**，单页最多扫描 195 段文字（名单页） |
| `a11y-check.mjs` | **17 项全 PASS**，22 条路由 375px 零溢出 |
| `screenshots.mjs` | 14 张全部 `status=200`，`scrollW` 恰好等于视口 |

`contrast-audit` 的实现要点：逐级向上收集祖先的半透明背景并合成真实底色。`bg-brand-soft/40`、`text-white/65` 这类写法在源码里看不出最终对比，必须算合成后的值。判定阈值按字号分档（≥24px 或 ≥18.66px+bold 用 3:1，其余 4.5:1）。

### 分组工作台加载偏移修复

一次 1280px 测量发现 CLS **0.1443**。逐帧记录确认：最近方案先到、成员资料尚未到时，卡片以 `#690` 这类短占位标识显示，高约 124px；随后姓名和学号到达，卡片长至约 316px，向下推动其他卡片。现改为方案与成员资料均就绪后再展示分组卡片；成员资料读取失败则显示独立错误与重试入口，而不是假装渲染成功。补充了两项回归测试，分别锁定延迟返回与 503 失败。更新生产构建后连续 **8 次**从页面首帧采集：分组工作台 CLS **7 次 0、1 次 0.0001**，原先 0.1443 的卡片偏移未再出现。这里是本机同一夹具下的重复测试，并非生产用户现场数据。

### 线上复验（http://47.97.96.242）

本地夹具是 24 组 / 216 任务，线上是真实 120 人课程，两者渲染出的分支并不完全一样，所以部署后又用同一批脚本打线上地址跑了一遍：

```powershell
$env:COPADDLE_BASE_URL='http://47.97.96.242'
node scripts/design-check.mjs   <cookie> 4     # 19 项全 PASS
node scripts/contrast-audit.mjs <cookie> 4     # 浅深两主题 0 处不合格
node scripts/a11y-check.mjs     4 <teacher> <captain>
```

**这轮抓到一个本地测不出的缺陷**：线上 120 人课程按默认分组设置分不出组，因此会渲染「按当前设置分不出组，先改参数」的 Callout，里面「去改分组策略」链接只有 **16px 高**（`text-xs` 且无纵向内边距），375px 巡检判为过小热区。本地夹具的 24 组 / 192 人正好能分组，这段 Callout 根本不出现，17 项全部 PASS。已补 `py-1.5`，热区变 32px。

教训：**夹具能覆盖规模，覆盖不了分支**。凡是「按数据不同才出现」的提示块，都要拿真实数据再跑一遍。

## 五、已知局限（请务必知悉）

**我没有亲眼看过这些截图。** 当前模型不支持图像输入（`read_image` 返回 `model "gpt-6.1-sol" does not declare image input`）。所以「眼前一亮」这个判断，只能用**可测量的断言**支撑：

- 字阶确实生效（Hero 65.6px、页标题 32px）；
- 橙色确实稀缺（3 处文字 + 1 处底）；
- 对比度确实达标（两主题 0 处不合格）；
- 主题变量确实在跟随（雷达图浅色/深色不同）；
- 布局确实没塌（22 条路由 375px 零溢出、14 张截图 scrollW 等于视口）。

这些能证明「没有做错」，但**不能证明「好看」**。截图在 `F:/GitHub/CoPaddle/.tmp-shots/`（14 张，已 gitignore），请你亲自过一遍——尤其是 `landing-desk.png`、`login-desk.png`、`grouping-desk.png` 这三张最代表设计意图的。

其他未覆盖项：

- 未在真实手机与真实读屏软件（NVDA / VoiceOver）上验证，375px 与键盘流程都是无头 Chrome 跑的；
- 未做改前/改后视觉对比截图（原样式已回退不了，只能给绝对值）；
- 深浅主题切换按钮的观感未单独验收，只验了两套主题下的对比度。
