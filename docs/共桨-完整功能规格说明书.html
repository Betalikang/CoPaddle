五条贯穿全案的设计决策

决策内容与理由
角色是局部的，不是全局的同一个学生可以在 A 课当队长、在 B 课当队员。因此角色存在 course_memberships 与 group_members 上，不能放在 users 表。这是最容易踩错的一处数据建模
算法独立成服务CP-SAT、图算法、LLM 编排的生态都在 Python。硬塞进 Next.js 会丢掉 ortools 与 networkx
溯源必须由系统产生，不靠自报段落级归属由「平台内撰写」这一行为天然沉淀。若让学生自己填「我写了哪段」，搭便车者只要会填表就能规避
贡献只输出区间，不输出分数规避 AI 判分争议。系统给决策依据，评分与调分权归教师。S4 有完整计算规则
硬约束在拖动时实时校验教师拖动组员若破坏硬约束，界面立即标红并禁止落库。软约束则可破坏，但要实时展示得分代价

为什么角色不能放在 users 表

这是整份规格里最容易埋雷的一处。用 users.role 存角色，会导致一个学生无法同时是「A 课队长 + B 课队员」。正确做法是：课程级角色存 course_memberships.role，小组级职责存 group_members.duty，权限判定时两者求交。

skill_cards        id PK · course_id FK · user_id FK · submitted_at

                   lead_count · member_count · is_first_timer

                   source(skill_card|history)      IDX: skill

social_edges       id PK · course_id FK · user_a FK users · user_b FK users
                   edge_type(same_group|same_class|co_edited|peer_rated)
                   weight NUMERIC(4,2) · last_at
                   UNIQ: (course_id, user_a, user_b, edge_type)
                   # 用于"弱连接引入度"计算与教师端社交图可视化

constraints        id PK · course_id FK · type(no_same_group|must_same_group|time_conflict)

preview-move 是整个产品最重要的一个接口

它是"答辩杀手锏"的技术支撑。拖动组员时前端每次放下都调它，后端不重新求解，而是拿当前方案在内存里重算四维得分并做硬约束校验，返回增量。因此延迟可以做到 50ms 以内，实现真正的"实时看到得分变化"。返回结构：{ ok, violations[], deltas:{skill_cover:+6, weak_tie:-11, ...}, total_before, total_after }

4.2　分组：硬约束与四维目标函数

硬约束（不满足即无解，拖动时实时校验）

H1  组规模         min_group_size ≤ |g| ≤ max_group_size
H2  不可同组       ∀(a,b) ∈ no_same_group : ¬∃g, a ∈ g ∧ b ∈ g
H3  必须同组       ∀(a,b) ∈ must_same_group : ∃g, a ∈ g ∧ b ∈ g
H4  同班限制       若 allow_cross_class = false，则组内成员 class_id 必须一致
H5  组数           |groups| = group_count，且每组非空
# 附加软校验（不阻止，仅提示）
W1  时间交集       组内成员可用时间交集为空时给出警告
W2  性别 / 群体均衡  若启用，则单性别小组与孤立个体给出警告（不阻止）

四维软目标（0–100，越高越好；教师端用滑块调权重，范围 0–2）

# 记 cap(m,d) 为成员 m 在能力维度 d 上的水平（0–5），D 为 7 个能力维度

# ── 维度 1：技能覆盖度（默认权重 1.2）──
cover(g)      = |{ d : max_{m∈g} cap(m,d) ≥ 3 }| / 7
score_skill   = 100 × ( 0.7 × mean_g cover(g) + 0.3 × min_g cover(g) )
# 取 min 是为了惩罚"有一组技能严重残缺"，而不是只看平均

# ── 维度 2：弱连接引入度（默认权重 0.8）──
strong(a,b)   = 存在 social_edges(a,b) 且 weight ≥ 0.5
novelty(g)    = 1 − 强连接对数(g) / 总对数(g)
score_weak    = 100 × mean_g novelty(g)
# 高弱连接 ≠ 刻意打散熟人，而是避免小组退化成小圈子

# ── 维度 3：组间均衡度（默认权重 1.0）──
power(g)      = Σ_{m∈g} Σ_d cap(m,d)
score_balance = 100 × clip( 1 − std(power) / mean(power), 0, 1 )
# 防止强人抱团，也防止把落后者全堆在一组

# ── 维度 4：历史搭档规避（默认权重 1.0）──
repeat(g)     = |{ (a,b) ∈ g×g : 上一轮同组 }| / 总对数(g)
score_hist    = 100 × ( 1 − mean_g repeat(g) )
# ⚠ 伦理红线：该指标只用于"避免重复分组"，不用于标记个人。
   不得向学生公开，每学期清零历史，防止污名化的自我实现预言。

# ── 总分 ──
total = Σ w_i × score_i / Σ w_i

4.4　进度感知与健康度

# ── 延误判定（纯规则）──
任务延误      now > due_at AND status NOT IN (done, cancelled)
关键路径延误  max( now − due_at ) over { 关键路径上未完成且已过期的任务 }
关键路径      任务 DAG 上 est_hours 之和最大的一条链

# ── 三维健康度（0–100，越高越好）──
阻塞定义      status = blocked，或 前驱任务未完成且其 due_at 已过期
blocked_score  = 100 × ( 1 − 阻塞任务数 / max(1, 未完成任务数) )

失联定义      近 idle_trigger_days 天（默认 3）无任何 progress_signals
idle_score     = 100 × ( 1 − 失联成员数 / 组内人数 )

过载定义      剩余工时 > 距截止剩余天数 × 6 小时/天
overload_score = 100 × ( 1 − 过载成员数 / 组内人数 )

综合健康度     = 0.4 × blocked_score + 0.3 × idle_score + 0.3 × overload_score
              # 阻塞权重最高：它最容易连锁波及下游

（最高频）		 图算法 任务 A 的 due_at 变更或状态变为 blocked/delayed，且存在 B 满足 A ∈ B.deps 且 B 未完成 → 生成冲突，并计算波及的任务集合与预计顺延天数
契约冲突 规则匹配 ① 同一术语在 contract_glossary 有定义，但产出段落中出现了不同定义或单位；② 交接物的字段名与 contract_interfaces 不符
语义冲突 LLM 调用点 2 先规则筛选，再调模型（这条很重要，否则会过度调用）：候选段落对需同时满足 —— 属于同一 artifact、作者不同、覆盖同一任务范围、文本相似度落在 0.30–0.85 之间。
相似度 < 0.30 视为无关；> 0.85 视为重复（走"内容重复"分支，不需要模型判断）。只有中间这段才真正需要语义理解。

4.7　贡献归因计算规则（核心）

三类证据加权，权重来自 course_settings，默认 产出物 0.5 / 过程 0.3 / 同伴 0.2，三者之和必须为 1.0。所有计算不使用大模型。

证据 A · 产出物（artifact）

对成员 m：
  w_main(m) = Σ { seg.word_count : seg.author_id = m 且 seg.kind ∈ {paragraph, heading} }
  w_coop(m) = Σ { seg.word_count : seg.revised_by = m 且 seg.author_id ≠ m }

  w_total(m) = w_main(m) + 0.5 × w_coop(m)
  # 协作为主责的一半权重：审阅修改的分量应低于原创产出

  A(m) = 100 × w_total(m) / Σ_m w_total(m)

证据 B · 过程（process）

on_time_rate  = 按期完成的主责任务数 / 主责任务总数
cp_credit     = 完成的关键路径任务数 / 关键路径任务总数
rework_penalty= 1 − min( 1, 本人主责任务的总返工次数 / (2 × 主责任务数) )
help_credit   = min( 1, 主动补位次数 / 3 )   # 补位 = 承接他人放弃的任务

P_raw(m) = 0.35×on_time_rate + 0.30×cp_credit + 0.20×rework_penalty + 0.15×help_credit
P(m)     = 100 × P_raw(m) / Σ_m P_raw(m)

证据 C · 同伴（peer）

peer_median(m) = 去掉最高最低各一个后的中位数（评价人数 ≥ 4 时）
                 # 人数 < 4 时直接取中位数，不做去极值
Peer_raw(m) = ( peer_median(m) − 1 ) / 4        # 5 分制映射到 0–1
Peer(m)     = 100 × Peer_raw(m) / Σ_m Peer_raw(m)

若本轮无互评数据（轮次未开或未提交）：
  → 该维度整体缺席，其权重按 0.5 : 0.3 的比例重新分配给产出物与过程
  → 并在账本上标注"缺同伴证据，区间已放宽"

合成：点估计 + 区间估计 + 置信度

point(m) = w_a × A(m) + w_p × P(m) + w_peer × Peer(m)

# ── 区间宽度由证据充分度决定，这是"诚实表达不确定性"的实现 ──
evidence_coverage = min( 本人段落字数 / 组内平均段落字数,
                         主责任务完成数 / 组内平均主责任务数 , 1 )
peer_agreement    = peer_median 的 1 − 变异系数（互评一致性）

uncertainty = 6 × ( 1 − evidence_coverage ) × ( 1 − peer_agreement )   # 百分点
low  = point − uncertainty
high = min( point + uncertainty, point + 8 )     # 上限封顶，避免区间过宽失去意义

# ── 置信度分档 ──
evidence_coverage ≥ 0.7 且 peer_agreement ≥ 0.7  →  高
evidence_coverage ≥ 0.4 且 peer_agreement ≥ 0.4  →  中
其他                                              →  低

# ── 搭便车提示（阈值来自实证研究，可在答辩时说明来源）──
fair_share_ratio = point(m) / ( 100 / 组内人数 )
fair_share_ratio < 0.14  →  生成提示文案
# 提示文案必须同时说明：该研究也表明贡献不均与团队成绩无稳定关联，
   因此仅作提示，不构成扣分依据。

# ── 最终判定 ──
系统输出：区间 + 置信度 + 可下钻证据 + 提示
教师终审：填写 adjusted_low / adjusted_high / final_note，写入 attribution_reviews
系统永不输出单一分数，也永不自动生成成绩。

为什么坚决不输出分数

一旦系统给出「你 61 分」，就会出现三种后果：学生质疑算法、教师放弃使用、学生开始优化"让系统觉得我在干活"而不是真的干活。输出区间 + 证据，把终审权留给教师，是这个模块唯一可持续的设计。这条不是保守，而是产品能不能被真正采用的分界线。

AI 能力规格

结论重申：六个模块中只有 2 个需要大模型。其余用求解器、图算法、规则与模板。配套代码已在 gongjiang-ai/ 落地并跑通。

6.1　大模型调用点 1：作业要求 → 任务 DAG + 协作契约

项目规格
触发时机队长或教师上传作业要求（文本粘贴 / PDF / DOCX）后点击"生成任务计划"
输入作业要求原文（截断至 12000 字）+ 小组人数 + 课程名 + 剩余天数
输出结构TaskPlan { tasks: TaskNode[], contract: Contract }，见 schemas.py
提示词要点① 粒度 2–8 小时，总数 ≤ 12；② 必须显式声明依赖，不允许孤立任务；③ id 编号规范且 deps 必须真实存在；④ 交付物形态要具体；⑤ 同时产出一份含术语、口径、单位、交接格式的协作契约——这是抑制冲突的根治手段
后置校验纯规则：重复 id、悬空依赖、成环。ai.py:validate_plan() 已实现。校验失败的条目在队长端高亮标出并要求人工修正，不静默丢弃
参数temperature = 0.2（低温度保证结构稳定）；response_format = json_object；超时 90s
失败处理重试 1 次；仍失败则提示"AI 暂不可用"，提供手工创建任务入口，并保留原文供参考
调用频率每组每次作业 1 次，失败重试最多 1 次。一个 50 人 × 8 组的课程，一学期约 8–16 次调用

6.2　大模型调用点 2：语义冲突归因

项目规格
触发时机规则层筛出候选段落对后，由队长或教师确认发起（不自动批量调用）
前置筛选同一 artifact · 作者不同 · 覆盖同一任务范围 · 文本相似度 ∈ [0.30, 0.85]。这一步把绝大多数无关文本挡在模型之外，是控制成本的关键
输入两段产出（各截断 4000 字）+ 协作契约中的术语与口径约定 + 双方姓名
输出结构ConflictAttribution { kind, severity, reason, suggestion, merged_text }，见 schemas.py
kind 取值口径不一致 / 接口不匹配 / 结论实质矛盾 / 内容重复 / 无冲突
提示词要点① reason 必须引用双方原文片段，不允许空泛评价；② 传入已生成的协作契约作为判定依据——这让归因有了客观锚点，而不是模型的主观感觉；③ 严重度按"对最终交付物的破坏程度"判定
失败处理重试 1 次；失败则降级为"人工判断"，界面仍展示双方原文对比与契约条款
调用频率每次冲突 1 次。实际课程中冲突数量有限，整个学期通常在 20 次以内

6.3　非大模型的 AI 能力（确定性的"智能"）

能力实现方式为什么不用大模型
多目标最优分组约束求解器 OR-Tools CP-SAT模型无法保证满足硬约束，也无法给出可证明的解。求解器能，且更快更准
拖动实时得分反馈内存中重算四维得分毫秒级要求，任何模型调用都做不到
关键路径 / 波及分析图算法（拓扑排序 + 最长路径）确定性图论问题，有唯一正确解
健康度三维阈值规则指标定义完全确定，模型只会引入不稳定
重规划三方案排序贪心规则明确（技能匹配 × 空闲度），可解释性要求高
依赖冲突检测图遍历纯结构问题
贡献归因计算加权公式 + 区间估计数值由公式算出，模型没有增量信息；且必须可复现、可指向公式
分组方案解释模板拼装模型会为既定数字编造理由。templates.py:explain_grouping()
贡献说明与搭便车提示模板拼装同上。templates.py:explain_contribution() / check_fair_share()
互评异常检测统计规则规则可枚举，不需要语义理解

这条边界怎么在答辩时讲

如果评委问"你们的 AI 含量在哪"，答案是三段式：
「我们用大模型做两件事——读懂作业要求，判断两段产出是否矛盾。这两件事都需要理解人写的文字，是模型不可替代的。
分组用约束求解器，因为它能保证满足硬约束并给出可证明的最优解，这是模型做不到的。
归因和解释全部用公式与模板，因为数值是我们算出来的，让模型去解释只会编造理由。」
主动划出这条边界，比标榜"全流程 AI 驱动"更能体现工程成熟度。

7.4　隐私与合规

本产品采集学生行为数据，必须守住四条

  • 最小必要：只采集达成功能所必需的数据。不采集与协作无关的行为（如鼠标轨迹、页面停留时长）。
  • 可开关：协作行为信号（编辑痕迹、打卡）提供开关，学生可关闭，关闭后该维度证据缺失并在账本上标注"证据不足"，而不是直接判低分。
  • 可查看：提供"系统知道我什么"页面（/api/me/data-export），学生可导出系统持有的全部个人数据。
  • 不外泄：协作倾向与历史指标不向学生互见，教师可见但不导出到成绩单。社交联系图仅教师可见。
