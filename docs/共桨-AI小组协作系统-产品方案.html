01

问题定义：我们卖的不是"分得准"

小组协作产品的直觉答案是"把组分好"。但分组一学期只发生一次，而痛苦每天都在发生。

高校小组作业的真实失效链路是这样的：教学要求规定了分组形式，但没有规定协作过程。于是责任在分组那一刻就被切断了——老师只在终点看到一份署了四个名字的文档，队长在中间当人肉调度器，队员在黑箱里等活。

教师视角
只在终点看到结果。过程不可见，无从干预，只能凭署名顺序给分。
队长视角
承担了调度责任，却没有调度权威。催办靠人情，怕得罪人，最后自己兜底。
队员视角
不清楚"我到底负责什么"、依赖谁、什么时候必须交。规则不透明，也没处申诉。

三个被忽视的结构性断点

断点表现根因
分完组就失联任务分完没有任何后续跟踪，中途崩盘无人知晓，直到截止前一天缺少过程数据的采集入口
没人有合法权威催办同学之间不好意思催，队长怕得罪人，老师没有介入的理由协调责任没有制度化载体
贡献无法公平归因"搭便车"现象普遍，但拿不出证据，只能自由心证协作过程没有留下可复核的痕迹

我们的核心主张

把教师的角色从终点裁判变为过程中可介入的调度者；把同学之间"不好意思说的话"交给中立的系统去说；把"贡献"从主观印象变成可复核的证据链。分组只是入口，真正的产品是那个一直在线的调度中枢。

一句话定位：共桨把「小组作业」从一次性分工，变成一条有据可查、可调度、可归因的协作流水线。
02

三个角色，三种被授权的稀缺能力

角色的划分不是界面分区，而是把三种原本不存在的"授权"交到三种人手上。

教师端

拿到的是过程里可介入的合法理由

  • 建课、导入班级名单
  • 设定约束：组数、人数、不可同组、评分权重
  • 审核 AI 分组方案（三选一 + 手动微调）
  • 过程中查看小组健康度与预警
  • 一键救火：重分 / 补位 / 降规模
  • 终审贡献账本并最终调分

队长端

拿到的是"不是我在针对你，是系统判定的阻塞"

  • 确认并微调 AI 生成的任务 DAG
  • 指定主责 / 协作 / 审阅人
  • 查看组内阻塞与负载失衡
  • 发起重规划（附 AI 方案背书）
  • 提交组内互评与队长评语

队员端

拿到的是看得见的透明规则与申诉权

  • 看到"我的部分 / 依赖谁 / 何时必须交"
  • 在平台内产出交付物（自动溯源）
  • 申请延期、请求支援
  • 发起冲突仲裁
  • 查看自己的贡献账本与申诉入口
03

AI 调度引擎：六个模块

这是产品的技术主体。每个模块都对应赛题要求的"AI 直接参与核心过程"，而不是外挂一个聊天框。

M1　班级画像理解

输入教务成绩（可选）、历史小组作业记录、30 秒技能自选卡、以往互评、可选协作行为信号
处理构建多维画像：能力向量（编程/写作/设计/表达/数据分析）+ 协作倾向（主责完成率、延期率、被依赖度、补位次数）+ 社交联系图（历史同组、高频协作）+ 硬约束（时间可用性、不可同组名单）
输出班级画像图谱；每位学生一组可解释标签（不是黑箱分数）
冷启动首轮无数据时采用「均衡随机 + 硬约束满足」，从第二轮起切换真实画像。叙事价值：分组质量随学期复利上升——这本身就是续费理由

M2　多目标最优分组

关键认知纠正："联系度最优"如果被理解成"和熟人一组"，方向就是错的。真实最优是能力互补 + 弱连接引入 + 组间公平 + 历史搭便车者规避。目标函数见 第 04 节。

处理硬约束裁剪 → 图划分 / 局部搜索（小规模可求 ILP 精确解）→ LLM 生成候选方案并产出自然语言解释
输出三个候选方案，每个附「为什么这样分 / 代价是什么」
交互亮点教师手动拖动微调时，实时显示目标函数得分变化——"这样调整会牺牲 12% 的弱连接引入度"。这是答辩现场最容易做出效果的一处

M3　任务拆解与分配

输入作业要求原文（PDF / 链接 / 教师口述）
处理LLM 解析为任务 DAG：里程碑 → 子任务 → 依赖关系 → 预估工时 → 所需技能 → 交付格式。再按技能匹配 + 负载均衡做 RACI 分配（主责 R / 协作 C / 审阅 A）
同时产出小组协作契约：术语表、接口约定、交付格式模板。这是抑制冲突的根治手段，不是事后补救
输出每人一份"我的部分"清单；组长一个甘特 + 看板视图

M4　实时进度感知

设计原则：不依赖人上报

让同学每天汇报进度是产品自杀。所有信号必须从协作行为里自动沉淀：交付物版本与编辑痕迹、看板状态变更、里程碑打卡、可选的 Git / 在线文档协作者记录、消息响应时延。

核心能力是关键路径监控：关键路径上的任务一旦滞后，系统提前预警而非事后告状。输出「小组健康度」三维读表——阻塞 / 空转 / 过载。

M5　冲突检测与合并

依赖冲突
（主战场）		A 的产出是 B 的输入，A 延期或改口径 → 立即检测，评估下游波及幅度，触发重规划
契约冲突术语、格式、接口不一致 → 基于协作契约做语义 diff，给出就地合并建议
内容冲突语义相似度只作辅助信号，不作为主判据（用文本相似度检测协作冲突是打偏靶子）
输出冲突单 + 三种解法：就地合并 / 退回对齐契约 / 重指派

M6　贡献归因账本

详见 第 06 节——这是整个产品的价值闭环，也是最需要谨慎设计边界的地方。

04

分组不是一个"算法"，是一个带约束的多目标优化

能在答辩现场把目标函数写清楚、把权重来源说清楚，就是硬实力。含糊地说"AI 智能分组"是会被追问到穿帮的。

# 目标（对候选分组方案 S 求最大）
max   w₁ · 技能覆盖度(S)　　　# 组内技能维度覆盖，避免全员同质
    + w₂ · 弱连接引入度(S)　# 社会学：弱连接带来信息增量
    − w₃ · 组间实力方差(S)　# 公平：不让强人抱团、不把落后者堆一组
    − w₄ · 历史搭便车重复率(S) # 避免与历史低贡献同伴重复同组
# 约束（硬性，先裁剪可行域）
s.t.  组数 = 教师指定　　　　　　　# 硬约束
     每组人数 ∈ [m, M]　　　　　# 规模约束
     不可同组配对 ∩ S = ∅　　　# 时间冲突、主动申请回避
     队长人选互斥　　　　　　　# 每队恰好一名队长

权重怎么定？不能拍脑袋。三个来源：教师首次建课时用滑块设定（默认值由学科类型推荐，如理工科给 w₁ 更高、文科给 w₂ 更高）、上一轮的学生满意度互评回流、以及系统保留一个"公平优先"预设档给有特殊需求的班级。

一条必须写进产品里的伦理红线

w₄ 历史搭便车重复率 用得不当会造成污名化——被系统标记过一次的人，可能永远分不到好组，形成自我实现的预言。我们的处理是：该指标只用于"避免重复"而非"标记个人"，不向学生公开，且每学期清空一次历史。这件事在答辩上讲出来，比闷声做掉的分数高得多。

05

滚动重规划：产品真正的护城河

分组是静态的，协作是动态的。一次性的"最优分组"只是起点，持续的重规划才是产品持续被打开的理由。

重规划的触发条件有四类：关键路径滞后（最核心）、成员失联超过阈值、任务返工超过两轮、外部条件变更（老师改要求 / 截止日期变动）。触发后 AI 给出的是一个决策包，而不是一条告警：

方案 A · 重新分配
把滞后任务的子块转移给当前有空档且技能匹配的成员，附预计完成时间
方案 B · 缩减范围
标出非必要交付项及砍掉后的影响评估，供教师确认
方案 C · 组间补位
从其他进度领先的小组临时借调人力，需教师授权

每个方案都带代价说明（谁的工作量增加多少、哪个里程碑受影响、对最终评分的影响区间）。教师或队长一键采纳，系统自动重算 DAG、重发任务、更新看板。

为什么这条护城河很难被抄

通用项目管理工具（飞书项目、Notion、腾讯文档）都有看板和甘特，但它们没有教学语境下的约束——不知道什么是"公平分组"，不理解"课程评分权重"，更不会替老师做"这个组要不要救"的判断。我们的壁垒在教育语义层，不在可视化层。

06

贡献归因账本：不输出分数，输出证据

你提出的"量化每个人的成果"是整个产品最值钱、也最容易做死的部分。我们的答案很明确：绝不输出单一分数。

输入：三类可复核证据

证据类型 一
产出物溯源
最终交付物里哪一段、哪个文件、哪个图表由谁产出。基于版本记录与编辑痕迹，不靠人自报。
证据类型 二
过程行为
主责完成任务数、按期率、关键路径延期次数、返工轮次、主动补位次数。
证据类型 三
同伴证据
组内互评（去极值后取中位）、队长评语、跨组可见的协作评价。

输出：贡献构成 + 区间估计 + 可追溯条目

主责产出 · 建模脚本34%
协作产出 · 数据清洗12%
审阅与返工 · 图表修订9%
主动补位 · 摘要撰写6%

系统结论：贡献度区间 58%–64%，置信度 中。每条结论均可下钻查看原始证据（版本记录、看板日志、互评原文）。

系统不输出分数，终审权与调分权归教师。

五条设计红线

  1. 只给依据，不给分数系统输出的是决策依据，评分与权重由教师终审。规避"AI 判分"引发的一次性信任崩塌——只要出一次争议，老师就再也不敢用了。
  2. 输出区间与置信度，不输出点值58%–64% 比 61% 诚实，也更能抵御质疑。诚实地表达不确定性，是产品的成熟度。
  3. 每条结论可下钻到原始证据可复核、可质疑。没有证据的结论不允许出现在界面上。
  4. 设申诉与更正通道队员可提交补充证据、可发起复议。有申诉机制的产品才能被学生接受。
  5. 防博弈设计互评异常检测（识别互刷高分的小圈子）、产出物溯源权重高于活跃度、教师可调整三类证据的相对权重。

必须直面的 Goodhart 定律

分数一旦成为目标，同学们就会去优化"让系统觉得我在干活"，而不是真的干活。我们的应对不是追求完美的检测算法，而是从产品定位上就不把数字当唯一目标——把"系统给出的不是成绩，是证据"明确写进产品文案与教师侧说明。主动承认这个边界，反而比假装能解决它更有说服力。

08

MVP 范围与实现路径

竞赛演示需要一条"能跑通的完整闭环"，而不是功能清单。以下六步构成可演示的最小链路。

步骤演示动作展示的 AI 能力
01教师建课、导入 30 人名单，学生填写技能自选卡理解 · 画像构建
02AI 生成三个分组方案并给出解释，教师拖动微调，实时看到得分变化规划 · 判断 · 多目标优化
03上传作业要求 PDF，自动生成任务 DAG、分工方案与协作契约理解 · 生成
04队员在平台内提交交付物，进度看板实时更新健康度识别 · 进度感知
05模拟一名成员延期，系统触发关键路径预警并给出重规划决策包识别 · 判断 · 重规划
06生成贡献归因账本，点击任一条结论下钻到原始证据归因 · 可解释性

答辩的杀手锏：把两个东西做成可视化

一是分组目标函数——拖动组员时实时显示四项得分的增减曲线，让评委直观看到"多目标优化"不是口号；二是贡献归因证据链——从结论一路点回到原始版本记录。这两处做扎实，比堆十个功能更能拉开差距。

09

风险与规避

风险为什么致命规避策略
学生不愿迁移协作入口 数据采不到，整条产品链归零。学生习惯微信 / QQ / 腾讯文档 低摩擦回流（粘贴 / 导入 / 截图解析）；与主流文档工具打通；只强制"最终交付物"在平台内
AI 判分引发公平争议 只要出一次争议，教师群体就再也不敢用 只给依据不给分；输出区间与置信度；教师终审；证据可下钻；申诉通道
数据冷启动 首轮分组不准，口碑当场崩掉 首轮"均衡随机 + 硬约束"；技能自选卡 30 秒补齐；明确告知质量随数据复利上升
教师使用成本高 B 端不买单，产品没有付费方 教师端只做三件事：建课、审核、救火，其余全自动。默认值开箱即用
学生行为数据隐私 采集行为数据敏感，政策与伦理双重风险 最小必要采集；每项信号可开关；脱敏展示；提供校级本地化部署选项；学生可查看"系统知道我什么"
搭便车标记的污名化 被标记者可能永远分不到好组，形成自我实现的预言 历史指标只用于"避免重复分组"，不用于标记个人；不向学生公开；每学期清空
10

赛题契合度：AI 六项能力全覆盖

赛题明确要求"AI 应直接参与理解、生成、识别、判断、规划或交互等核心过程"。我们的六个模块逐项对应，不留空档。

能力在产品中的具体落点
理解读懂作业要求原文，拆出任务与依赖；读懂班级画像与成员差异
生成生成任务 DAG、生成小组协作契约、生成重规划决策包、生成分组方案的自然语言解释
识别识别关键路径滞后、识别依赖断裂、识别契约不一致、识别搭便车与互评异常
判断判断谁能补位、判断冲突归因、判断该不该触发重规划、判断贡献构成
规划多目标分组规划、任务分配规划、滚动重规划
交互以中立第三方身份向成员发送提醒、催办与协调通知——把同学之间"不好意思说的话"交给系统说，这是产品最独特的一处交互设计

赛题还强调"重新设计人与人建立联系的方式"。共桨的答案不是让人际关系更热闹，而是让协作责任变得可见、可分配、可追溯——用制度设计替代人情消耗。

差异化：与既有方案的真实对比

诚实地说，这个赛道不是空白。学术界的实际对标是 Purdue 的 CATME——团队组建 + 同伴评价系统，已经用了十几年。我们必须说清楚自己多了什么。

维度CATME（学术界对标）通用项目管理工具共桨 CoPaddle
分组问卷 + 静态规则匹配不具备多目标优化 + 可解释 + 实时调优反馈
过程跟踪无（仅期末自评互评）有看板，但无教学语义关键路径监控 + 提前预警
动态调整无靠人手动改AI 滚动重规划决策包
贡献归因纯主观自评互评无交付物级溯源 + 证据链
冲突处理无无依赖断裂检测 + 前置协作契约
中文场景英文界面，海外教学语境通用本土教材与工具链打通
